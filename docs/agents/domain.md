# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` at the
root and architectural decisions under `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. Create them lazily through
domain-modeling when terms or decisions are resolved.

Use the glossary’s vocabulary in specs, code, and tests. Surface
conflicts with existing ADRs explicitly.
